## 1. Objective and scope

Phase 1 establishes the .NET/WPF solution and the boundaries needed by later approved phases: centrally managed configuration and package versions, encrypted-database/migration/key interfaces, secure logging and error boundaries, a password-hash primitive, initial tests and Windows CI, and the first read-only design-token/application-shell scaffold.

This is **not** a clinic application suitable for real data. The screen deliberately exposes no patient, clinical, appointment, prescription, billing, inventory, backup, or settings workflow. No such requirement is marked accepted by this report.

## 2. Architecture decisions made in this phase

- .NET 10 LTS, C#, and a WPF `win-x64` desktop target; shared domain, application, infrastructure, migration-tool, and test projects target `net10.0`.
- A modular-monolith solution with separate `Domain`, `Application`, `Infrastructure`, `Desktop`, and test projects. EF design-time tooling is isolated in a non-shipping console project.
- NuGet versions are centrally pinned in `Directory.Packages.props`; `global.json`, a local `dotnet-ef` manifest, warnings-as-errors, NuGet auditing, and generated package lock files are part of the build policy. The first Windows CI run will generate the lock files; they must be committed and CI switched to locked restore before the phase can close.
- EF Core 10 with `Microsoft.EntityFrameworkCore.Sqlite.Core` uses the `SQLite3MC.PCLRaw.bundle` 2.4.0 candidate. The bundle documentation says its default cipher is sqleet (ChaCha20-Poly1305); `Microsoft.Data.Sqlite`'s `Password` connection-string path is .NET 10-specific. The connection factory derives its password from a randomly generated 256-bit database key, not a login password. The exact native package load, encrypted header, wrong-key rejection, migrations, and Unicode round-trip are covered by Windows integration tests, pending execution.
- The database key is stored only as a DPAPI `CurrentUser`-protected envelope under the user's local application-data directory. A corrupt existing key fails closed rather than being silently replaced. The key is not in appsettings or the executable directory.
- NSec.Cryptography 26.4.0 supplies Argon2id v=19 at 19,456 KiB, two passes, one lane, a 16-byte random salt, and a 32-byte verifier. This follows the OWASP minimum baseline, not a final performance calibration. The hash parser accepts only the exact supported parameter set and has bounded input sizes.
- The EF design-time project creates a random-key encrypted in-memory database. It has no route to the per-user clinic database.
- The app shell defaults to `bn-BD`, uses Bengali-capable Windows font selection and BDT/poisha tokens, and shows a static Phase 1 status only. It does not initialize or migrate a clinic database on screen startup.

## 4. Dependency and licensing notes

Directly selected Phase 1 packages and initial versions:

- Microsoft EF Core SQLite Core / Design: `10.0.12` (MIT).
- SQLite3MC PCLRaw bundle: `2.4.0` (MIT wrapper; default sqleet cipher source is public domain/Unlicense). The bundle depends on SQLite3MC native/provider and SQLitePCLRaw packages; generated lock files and a later full native/transitive license notice audit are still required.
- NSec.Cryptography: `26.4.0` (MIT), based on libsodium `1.0.22`. Its Windows guidance notes a Microsoft Visual C++ Redistributable requirement; the hosted runner test is not proof that a clean customer machine has the required runtime. Resolve/bundle/install this dependency legally or choose a compatible alternative before release.
- Microsoft.Extensions.Hosting/abstractions and ProtectedData: `10.0.12`; MSTest and Microsoft.NET.Test.Sdk are pinned centrally. GitHub Actions are pinned to full commit SHAs in `.github/workflows/ci.yml`.

References: [SQLite3MC 2.4.0 package/readme](https://www.nuget.org/packages/SQLite3MC.PCLRaw.bundle/2.4.0), [NSec 26.4.0 package](https://www.nuget.org/packages/NSec.Cryptography/), [NSec installation/platform guidance](https://nsec.rocks/docs/install), and [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html). This is an initial dependency selection, not the release SBOM or legal clearance.

## 5. Tests and verification

### Automated cases added

- Domain: exact poisha conversion, fractional-poisha rejection, checked arithmetic, BDT/Bengali-culture formatting, UTC audit time, and rejection of free-form audit codes.
- Security: Argon2id version/parameters, unique salts, correct/wrong password, NFC Unicode equivalence, malformed/oversized input, protected key persistence, fail-closed corrupt key, concurrent key creation, and a Windows DPAPI CurrentUser round-trip.
- Database: new/repeated migration initialization, metadata persistence, encrypted-file header, wrong-key rejection, structured audit persistence, and Bengali Unicode stored/read through the native encrypted SQLite provider.
- Logging: arbitrary patient-name/phone values and exception messages are not written; only allowlisted operational codes and exception type remain.

### Results

- Local `dotnet --info`, `dotnet restore DentivaPro.sln`, `dotnet build DentivaPro.sln --configuration Release --no-restore`, and `dotnet test DentivaPro.sln --configuration Release --no-build` were attempted. All are blocked because this Debian 12 sandbox has no `dotnet` executable (`command not found`, exit 127); direct SDK/NuGet downloads were previously confirmed unavailable from this shell.
- Static checks passed for project XML, WPF XAML XML, JSON configuration, project-reference paths, and rough C# brace balance. These are not substitutes for compilation.
- Windows GitHub Actions build/test, EF model-snapshot check, package-lock generation, and package audit are **pending**. The report and phase status must be updated with the exact run URL and results before Phase 1 can close.

## 6. Known blockers and product-owner risks

1. **Public source repository:** GitHub repository visibility remains public. No visibility change was made. Do not place production credentials or signing secrets in source. The owner must confirm public-source intent or change repository visibility using an authorized account; this agent will not change it.
2. **Windows dependency/runtime:** NSec's documented VC++ runtime requirement needs a clean-client deployment decision; Windows-hosted CI may already have that runtime installed.
3. **Profile/key recovery:** DPAPI CurrentUser means loss or replacement of the Windows profile can make the database unreadable. No portable recovery flow exists yet.
4. **Native package and crypto audit:** transitive lock files, native runtime assets, complete notices, vulnerability result, and production performance calibration are pending.
5. **Platform evidence:** WPF cannot run in this Debian sandbox. Actual Bengali font fallback, PerMonitorV2 behavior, Windows 11 appearance, printer/PDF output, and clean install remain unverified.
6. **Data safety:** this development shell must not be used with clinic data; it does not implement the required clinical, financial, authorization, backup, or recovery workflows.
